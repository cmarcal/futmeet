# Routing with TanStack Router

The web app uses TanStack Router with file-based routes and automatic code splitting, on top of TanStack Start (Vite plugin). `react-router-dom` is no longer a dependency.

## Layout

```
apps/web/src/
├── routes/                    ← one file per route (flat dot notation)
│   ├── __root.tsx             ← document shell (HeadContent/Scripts, global CSS via ?url) + ErrorBoundary/Outlet
│   ├── index.tsx              → /
│   ├── game.$gameId.tsx       → /game/$gameId
│   ├── results.$gameId.tsx    → /results/$gameId
│   └── waiting-room.$roomId.tsx → /waiting-room/$roomId
├── router.tsx                 ← getRouter() factory + Register type + default pending/error components
├── routeTree.gen.ts           ← GENERATED, committed, ignored by oxlint. Never edit by hand.
└── pages/                     ← page components (default exports) imported by route files
```

`routeTree.gen.ts` is regenerated by the TanStack Start Vite plugin on `dev` and `build`. It is committed so `tsc` and lint work on a clean checkout. There is no `index.html` or `main.tsx`: the document shell is `__root.tsx`.

## SSR (TanStack Start)

Selective SSR is per route: `ssr: false` on `/` and `/game/$gameId`; `ssr: true` plus `head()` (title, Open Graph) and a `beforeLoad` id check on `waiting-room/$roomId` and `results/$gameId`. Never set `defaultSsr: false`. Never put test files under `src/routes/` (they would become routes); use `src/__tests__/routes/`. The persisted Zustand store uses an inert storage on the server (`getGameStorage`), so SSR output is the empty state and the client rehydrates after hydration.

## Adding a route

1. Create `src/routes/<name>.tsx`:

```tsx
import { createFileRoute } from '@tanstack/react-router';
import MyPage from '../pages/My/MyPage';

export const Route = createFileRoute('/my/$id')({ component: MyPage });
```

2. Run `npm run dev` or `npm run build` once to refresh `routeTree.gen.ts`, and commit it.
3. Never use `React.lazy`/`Suspense` per page: `autoCodeSplitting` splits `component`, `pendingComponent`, `errorComponent` automatically.

## Hooks and navigation

```tsx
import { Link, Navigate, useNavigate, useParams } from '@tanstack/react-router';

const { gameId } = useParams({ from: '/game/$gameId' });

const navigate = useNavigate();
navigate({ to: '/game/$gameId', params: { gameId } });
navigate({ to: '/' });

<Link to="/results/$gameId" params={{ gameId }}>Results</Link>
<Navigate to="/" replace />
```

Paths are type-checked against the generated route tree (`Register` in `router.tsx`).

## Pending and error states

`router.tsx` sets `defaultPendingComponent` (LoadingSpinner) and `defaultErrorComponent` (ErrorFallback). Override per route with `pendingComponent` / `errorComponent` in `createFileRoute`.

## Testing

Use `renderWithRouter` from `src/test/renderWithRouter.tsx` (memory history, no mocks of the router):

```tsx
const { router } = await renderWithRouter(<GamePage />, {
  path: '/game/$gameId',
  initialEntry: `/game/${id}`,
});
await waitFor(() => expect(router.state.location.pathname).toBe('/results/' + id));
```

Pass a record `{ [path]: element }` to render several routes. Unmatched paths land on an empty splat route. Never `vi.mock` the router package; assert on `router.state.location.pathname`.
